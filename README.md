# Dirty Work Cleaner

> 面向审计基础执行工作的 AI 自动化工作流 —— 把实质性程序中最耗时的资料核查与整理环节，做成可复用的自动化流程。

审计实质性程序中，审计人员需要在合同、凭证、票据、函证等大量资料之间反复核对金额、日期与摘要，逐项比对、逐条登记，再整理成底稿。这部分工作规则明确、重复度高，却占据了现场执行的大量时间。

Dirty Work Cleaner 把这部分「脏活」拆成可自动化的模块，用**规则引擎处理可判定的字段，用大模型只处理规则覆盖不到的语义判断**，输出结构化的异常清单供审计人员复核。

---

## 核心模块

Web 版提供首页工作台与 7 个功能页面，对应审计执行流程中的不同环节：

| 页面 | 模块 | 作用 |
|---|---|---|
| 首页工作台 | — | 任务状态、处理轨迹、结果卡片与审阅摘要 |
| 凭证核查 | 规则引擎 | 判断附件是否到位、附件金额是否覆盖凭证金额 |
| 一致性检查 | 勾稽比对 | 抽凭清单 vs 实际凭证，金额与日期逐项比对 |
| OCR 处理 | PaddleOCR / 文本 | 票据、凭证影像转文本，含清洗与字段提取 |
| 地址核查 | 高德地理编码 | 比对函证地址与工商注册地址的坐标距离 |
| 企业信息填列 | 工商信息结构化 | 批量填列企业基础信息字段 |
| Supporting 整理 | 底稿整理 | 按科目归集 supporting 底稿并生成汇总 |
| 全局 AI 助手 | 结果解释 | 基于前述运行结果的问答式核查辅助 |

## 技术架构

```
Bottle (WSGI)  —— 15 条路由，服务端渲染
   ├── PaddleOCR        —— 凭证/票据影像识别
   ├── DeepSeek API     —— 语义判断层（OpenAI 兼容接口）
   ├── 高德地图 API      —— 地址地理编码
   └── pandas / openpyxl —— 表格处理与结果导出
```

### 一个刻意的设计取舍：规则优先，AI 兜底

金额、日期这类字段是**可判定**的，走确定性规则比对；只有摘要一致性这类**语义**判断才调用大模型。并且当模型的置信度低于阈值时，判定结果会**回退到规则结论**。

这样做的原因是审计场景的结论必须可追溯到具体依据——每一步判定都应该能回答「为什么这么判」，而不是「模型说是这样」。代码里这条边界是显式实现的，不是文档里的说法。

## 快速开始

```bash
cd DirtyWorkCleanerWeb

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

copy .env.example .env      # 填入 DEEPSEEK_API_KEY / AMAP_API_KEY
run.bat                     # 或 python app.py
```

浏览器打开 `http://127.0.0.1:8080`

两个 API Key 都**不是必需的**：未配置 DeepSeek 时，需要 AI 的页面会给出提示，规则类功能不受影响；未配置高德 Key 时，地址核查模块降级为规则比对，不做坐标距离核实。

### 服务参数

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `DWC_HOST` | `127.0.0.1` | 部署到云服务器时改为 `0.0.0.0` |
| `DWC_PORT` | `8080` | 监听端口 |
| `DWC_DEBUG` | 关闭 | 本地调试时可打开（含热重载） |

`samples/` 里的两个文件可完整复现五种一致性状态（一致 / 金额不一致 / 日期不一致 / 凭证缺失 / 多余凭证），复现步骤见 `docs/项目说明.md` 第 7 节。

`modules/` 与 `DirtyWorkCleaner/` 共享同一套业务逻辑：前者是 Web 版的运行时依赖，后者保留了命令行入口与测试样例。Web 版额外提供的是交互外壳（`app.py` + `templates/`）。

## 已知边界

这些是当前版本的明确边界，也是下一步的改进方向：

- **一致性检查的列名口径。** 抽凭清单侧读取的是「底稿金额」「底稿日期」，实际凭证表侧读取的是「凭证金额」「凭证日期」。若在抽凭清单里误用凭证口径的列名，所有匹配行都会落入「需人工复核」。`samples/` 下的示例文件已按正确口径命名。
- **跨模块状态。** 各功能页面之间结果不互相承接：一致性检查需要自行上传两个文件，而不是自动沿用凭证核查的输出。全局 AI 助手能读到最近一次运行的结果，但仅限一致性检查、地址核查、supporting 整理三个模块。
- **中文文件名。** Bottle 的 multipart 解析会丢弃文件名中的非 ASCII 字节，已加入按文件头的类型嗅探兜底，但**演示时建议统一使用英文文件名**。
- **OCR 依赖。** 图片识别依赖 PaddleOCR，首次调用会自动下载模型（数百 MB）。未安装时图片输入会提示，文本输入不受影响。
- **输入格式。** 当前支持 `xlsx` / `xls` / `csv` 与图片格式，PDF 输入尚未支持。
- **并发。** 开发服务器为单进程同步模式，适合本地演示与小规模试用，生产部署建议前置 WSGI 容器，并补上大模型调用的请求超时。

## 关于本仓库

- 项目背景、系统架构、设计取舍与可复现的演示路径，详见 [`docs/项目说明.md`](docs/项目说明.md)。

- 仓库内所有示例数据均为虚构：凭证号以 `DEMO-` 开头，不对应任何真实业务。
- 项目最初部署于云服务器用于比赛演示，本仓库为代码归档与持续开发版本。
