# 示例数据

本目录下的全部文件均为**虚构演示数据**，凭证号统一以 `DEMO-` 或 `API2026` 开头，
公司名与人名为虚构值，不对应任何真实业务。

---

## 一、一致性检查用

上传到「一致性检查」页面，两个文件需同时使用：

| 文件 | 上传位置 | 列名要求 |
|---|---|---|
| `sampling_list_demo.xlsx` | 抽凭清单 | 样本序号 / 凭证号 / **底稿金额** / **底稿日期** |
| `voucher_list_demo.xlsx` | 实际凭证表 | 凭证号 / **凭证金额** / **凭证日期** / 附件数量 |

**注意列名口径。** 抽凭清单侧读取的是「底稿金额」「底稿日期」；实际凭证表侧读取的是
「凭证金额」「凭证日期」。若在抽凭清单里误用凭证口径的列名，所有匹配行都会落入
「需人工复核」——因为两侧是不同语义的数据，不能混用。

两个文件各自带一个「使用说明」工作表，写明预期结果。

### 实跑覆盖的状态

| 一致性状态 | 数量 | 涉及凭证号 |
|---|---|---|

| 日期不一致 | 1 | DEMO-2026-0007 |

汇总指标：总样本 7、异常数 4、异常率 57%。

## 二、OCR 处理用

`mock/` 下为模拟凭证影像，可用于「OCR 处理」页面。
注意：**图片识别依赖 PaddleOCR**，未安装时该页面只支持文本输入（`.txt`）。

| 文件 | 内容 |
|---|---|
| `mock/mock_voucher_01.png` | 应付立账会计凭证（采购原材料款，1,000,000.00） |
| `mock/mock_voucher_02.png` | 应付立账会计凭证（差旅费报销，45,580.50） |
| `mock/mock_ticket_01.png` | 电子发票（增值税专用发票，运输服务） |

这些图片按业务系统常见的版式绘制，**凭证号与会计科目编码保留了真实系统的层级格式**
（例如 `API2026010001`、`1001001.6602001001.000.000`），因为它们正是 OCR 字段提取
环节需要验证的对象；公司名称、经办人姓名已替换为虚构值。

用文本方式演示 OCR 环节时，可用 `../DirtyWorkCleaner/ocr_output.txt`，
它保留了 OCR 原始输出特有的断行与排版噪声。
